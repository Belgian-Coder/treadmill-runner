## Harness Setup Notes

| Command | What It Does |
|---|---|
| `Python runtime missing` | No harness command can run yet. Follow `docs/harness/no-python.md`: use a user-scoped, WinGet user-scope, `AGENTS_PYTHON`, or portable Python 3.12+ runtime, then rerun setup with that executable path. |
| `python -B .agents/manage.py setup` | Write-mode initializer for the current project. Syncs generated routing/adapters, initializes navigation maps and project context, links user-level skills unless skipped or a temporary smoke marker is present, then runs validation. |
| `python -B .agents/manage.py setup --check` | Read-only setup verification. It checks generated artifacts, project initialization state, validation, ripgrep availability, and user-level skill links; temporary smoke targets auto-skip global skill-link checks via `.agents/harness-smoke-target.json`. |
| `python -B .agents/manage.py setup --check --no-link-skills` | Read-only setup verification for temporary or inspection copies that must not claim Codex, Claude, or Copilot user skill folders. |
| `python -B .agents/manage.py project-kickoff --target <project>` | Read-only first-use planning for a target project: copy contract, install/update plan, one primary next action, source-vs-target command groups, project-context review, workflow command recommendations, and copyable chat prompts. |
| `python -B .agents/manage.py project-kickoff --target <project> --apply` | Runs the safe first-use sequence: install/update harness, setup, setup --check, status --fast, then reports project-context review status without starting or resuming workflows. |
| `python -B .agents/manage.py project-context-review --target <project>` | Reads generated project context and reports structured missing stack, commands, external systems, persistence, CI, config, generated-boundary, and validation facts. |
| `python -B .agents/manage.py project-context-review --target <project> --write-review` | Writes intermediate `docs/project/review/project-context-review.md` and `.json` answer artifacts without editing canonical project context. |
| `python -B .agents/manage.py project-context-apply-review --target <project>` | Previews how answered review artifact facts would be added to canonical `docs/project/project-context.md` without writing. |
| `python -B .agents/manage.py project-context-apply-review --target <project> --apply` | Writes answered review facts into a marker-bounded reviewed-facts section in `docs/project/project-context.md`; it does not rewrite other project context sections. |
| `python -B .agents/manage.py dotnet-context --target <project>` | Read-only .NET project context inspection for SDK/runtime, solution/project shape, build policy, CI command candidates, config key inventory, persistence, NuGet/feed policy, and validation candidates; it never runs restore/build/test/package/tool commands. |
| `python -B .agents/manage.py dotnet-context --target <project> --solution <solution.sln> --project <project.csproj>` | Narrows .NET context inspection to a selected solution and project for monorepos while keeping the same read-only no-restore policy. |
| `python -B .agents/manage.py dotnet-context --target <project> --dotnet-executable <path-to-dotnet>` | Uses a trusted local SDK executable for the same safe probes when the project-required dotnet is not first on PATH. |
| `python -B .agents/manage.py dotnet-context --target <project> --write-evidence` | Writes project-local `docs/project/dotnet-context/dotnet-context.json` and `.md` evidence artifacts without editing canonical `docs/project/project-context.md`. |
| `python -B .agents/manage.py dotnet-context --target <project> --baseline docs/project/dotnet-context/dotnet-context.json` | Compares the current static .NET context against a previous report and flags project, framework, NuGet source, or build-policy drift. |
| `python -B .agents/manage.py install-harness --target <project> --run-setup-check` | Copies the resolved standard feature profile, initializes partial-profile generated outputs with `setup --no-link-skills`, then runs `setup --check --no-link-skills` without depending on global user profile state. |
| `python -B .agents/manage.py install-harness --target <project> --profile minimal --with-feature story-workflow --dry-run` | Previews a feature-adjusted install and reports the resolved features, sorted source file manifest, and stable SHA-256 digest without writing the target. |
| `python -B .agents/manage.py harness-promote --target <project> --dry-run` | Classifies consumer harness edits against the source payload and install manifest before any selected file is promoted back. |
| `python -B .agents/manage.py install-harness-smoke --fast --format json` | Creates a temporary target, writes `.agents/harness-smoke-target.json`, verifies clean copy exclusions, runs no-link setup checks, project-context check, and startup navigation proof, skips local AI/workflow start-resume, and removes the target unless `--keep` is used. |
| `python -B .agents/manage.py install-harness-smoke --format json` | Runs the full temporary-target dogfood: prepared install, smoke marker, clean-state check, no-link setup, project-context check, startup navigation proof, portable ripgrep/local-AI preparation, workflow start/resume, context packet check, and consumer workflow smoke. |
